# CLAUDE.md — working on Data Syncer

Read this before changing anything. `Docs/` has the detail.

## What it is
A Mac app (Swift + SwiftUI, macOS 14+, no Xcode project — SwiftPM + `BUILD_APP.sh`) that copies a
local source folder to one or more destinations **only when the user presses Run**: a sync (mirror),
a dated full backup, or full + incremental backups with restore. Never a service, never automatic.
The person using it is not a developer — every message is a plain sentence.

## Map
- `Sources/DataSyncerCore/` — everything that copies, compares, records and restores; no UI, tested on its own.
  - `Models.swift` — Job, Destination (kind + mode + folder), FileMeta, Snapshot, DSError (the only error type).
  - `Storage.swift` — the `Storage` protocol every destination kind implements, and `LocalStorage`.
  - `Scanner.swift` — a source folder → Snapshot (everything; nothing skipped except a `.datasyncer` at its top).
  - `Records.swift` — the `.datasyncer` records (README, destination, sync-state, manifests), backup folder names, `BackupCatalog` and chains.
  - `Planner.swift` — pure planning: what a sync or backup will do, before anything is copied.
  - `Runner.swift` — `JobRunner`: checks → plan → copy, one destination after another, with events and cancellation; `StorageFactory`.
  - `Restore.swift`, `Preflight.swift` (Check destinations), `JobStore.swift` (jobs.json in Application Support), `RunHistory.swift` (runs.json).
  - `Secrets.swift` (Keychain, one secret per destination id), `Shell.swift` + `SSHStorage.swift` + `SSHInfo.swift` (SSH through `/usr/bin/ssh`), `NetworkShare.swift` (mounted shares, NetFS).
  - `Cloud/` — `HTTP`, `OAuth` (PKCE + loopback listener on port 45873), `CloudAccounts` (accounts.json + Keychain `cloud:<id>`), one `Storage` per service: `S3Storage`, `GoogleDriveStorage`, `DropboxStorage`, `OneDriveStorage`.
- `Sources/DataSyncer/` — the SwiftUI app. Thin: `AppModel` drives the core and `RunSession` shows its events; views never touch disks (`Docs/ARCHITECTURE.md` lists the files).
- `Tests/DataSyncerCoreTests/` — XCTest against throwaway folders (`Scratch`), a fixed clock for folder names.
- `BUILD_APP.sh` assembles the .app (+ `icon/DataSyncer.icns`; ad-hoc signed by default, `--sign` for a stable identity); `INSTALL_APP.sh` checks tools, tests, builds, copies to /Applications.

## Rules that exist for a reason (Matt's decisions, Oct 2026)
1. **One way, on demand.** The source is always local and is the truth. Nothing runs unless the user runs it; no scheduling, no watching.
2. **Three modes per destination:** `sync(deleteExtras:)` (preview first; deleting is a per-destination switch), `fullOnly`, `fullIncremental(chainStart:maxIncrementals:)`. A job maps one source to many destinations; the run goes **one destination at a time**, carries on after a failure, and reports everything at the end.
3. **Folder names** `yyyy_MM_dd_HHmm_Full_<title>` / `…_Incremental_<title>` (year first so Finder sorts; time so two a day don't clash). Two backups in one minute are refused.
4. **The records travel with the data** (`Docs/RECORDS.md`): `<dest>/.datasyncer/{README.txt,destination.json,sync-state.json}` and `<backup>/.datasyncer/manifest.json`. The README text is Matt's wording — keep it. Each manifest holds the whole source snapshot as of that backup, what it copied, and what was deleted since its parent, so chains and restores need nothing from the Mac that made them.
5. **The app never deletes backups** (no retention): the user does, in Finder or in the app (`RestoreSheet` → `RestoreEngine.delete`, after naming the dependents). Deleting a backup must break nothing except restores of incrementals that depend on it; the catalog is re-read at every run.
6. **The destination folder must already exist.** Data Syncer never creates it; a missing folder fails the check with a plain message. USB drives are found by name under `/Volumes`; every destination has a configured folder inside its location.
6a. **Second-review rules (Oct 13 2026, all verified by reproduction):** an unlistable source root fails the scan; dated backup folders at a sync destination are never extras; folders keep owner rwx; `destination.json` refuses only while that destination still exists and `otherJobIds == nil` means refuse; renames keep backup titles (`Job.renamed`); SSH uploads are size-checked server-side before `mv` and each client has its own control socket; an address only matches itself in share matching; a refused token refresh is remembered (`stopReason()`) so a destination stops after one problem; cloud chunk retries resync from the service's offset.
6b. **Nothing under an unreadable source path is ever "deleted"** (`Scanner.Result.unreadable` → `Planner`): sync deletions are held back and incrementals record no deletions there. **Writes never escape the destination**: `LocalStorage` lstats, never mkdirs over a link, refuses a path that resolves outside its root; restore does the same for its target. **Copies land under a temp name and are renamed into place** (local, SSH) so a failure or cancel never leaves a half file under a real name. **A sync deletes/replaces before it copies** (case-only renames, type changes). **A backup's manifest leaves out what it failed to copy** (`failed`), so the next incremental catches up. **One folder, one destination** (`destination.json` checked; `otherJobIds`). **An obvious wipe** (empty source, most of the destination) is a `SyncPlan.warning`: shown in the preview, refused without one. Every one of these has a test in `SafetyTests`.
7. **Change detection = size + modified date** with a 2-second tolerance (FAT drives). A sync also checks the destination against the `sync-state` record, so a tampered or vanished copy is put right. No fingerprints, no skip patterns, no compression, no encryption (plain copies, by decision).
8. **Restore rebuilds the chain**: the full, then each incremental up to the chosen point, into a folder the user picks; `removeDeleted` decides whether files recorded as deleted are removed or left. Whole-backup restores only (partial restores later).
9. **Incrementals:** `chainStart` is `lastIncremental` (increments of increments) or `lastFull`; `maxIncrementals` per chain, after which the next backup must be a full. An incremental that is not allowed is refused with the reason when asked for explicitly, and becomes a full when the choice was left open.
10. **Cancelling** stops mid-file; a backup that did not finish is removed so it is never mistaken for one. A sync saves its record on the way out.
11. **Cloud services through their own APIs** (Google Drive, Dropbox, OneDrive, S3): no desktop apps; each gets an in-app step-by-step setup guide. Secrets go in the Keychain, never in jobs.json, under `SecretAccount.destination(id)`; a destination's secret is removed with it.
10b. **Cleanup must not inherit cancellation**: a half-made backup is removed via `Task.detached`, the sync record is saved the same way, and cloud aborts go through `HTTP.sendIgnoringCancellation`. `copyOne` rethrows `CancellationError` (never "failed: cancelled"). Storages get `close()` after each destination (SSH drops its master connection).
11a. **Cloud rules:** no SDKs, plain HTTPS; a storage's `walk`/`list` and `stat` must report the same size and date for a file (the sync planner relies on it); links throw from `makeSymlink` (reported as skipped); uploads over 8 MB are chunked; the destination folder is made only by `makeRootFolder()` on the user's click ("Make this folder"). Google Drive uses `drive.file` only. Tests run against `FakeHTTP`; nothing has been tried against the real services yet (Oct 13 2026) — say so when reporting.
11b. **SSH through the Mac's own `ssh`** (owner decision, Oct 13 2026): no SSH library; `~/.ssh` keys, config, known_hosts and the agent work as in Terminal, and Settings → Accounts shows them (read only). Passwords/passphrases go through `SSH_ASKPASS`; never let ssh wait on a prompt (`BatchMode=yes` when there is no secret). Remote commands must work on GNU *and* BSD servers (`serverFlavour`). Tests run against a private sshd the suite starts (`TestSSHServer`).
12. **Scripts**: `-x`/`--long` options + `-h`; idempotent; plain-spoken; a failed build is never masked (output in `build/build.log`); ad-hoc signing means FDA/Keychain grants reset per rebuild — `--sign` with a Keychain certificate is the documented fix; `--universal` for other Macs. **Commits:** one per feature with a dated CHANGELOG entry; explicit `git add <paths>`; never push — Matt pushes.
13. **Testing:** `swift test`; every engine rule has a test against throwaway folders; never touch the user's real folders or Application Support in tests (`Scratch` + `JobStore(url:)`).
14. **Sync preview** is the runner's `confirmSync` hook; the UI answers it with a sheet on the *window* (not the run screen), through a `SyncPreviewRequest` that answers once. Progress events are throttled in `RunSession`, not in the core. The strip stays after a run finishes until dismissed. Dev hooks `DATASYNCER_HOME` / `DATASYNCER_AUTOSTART` / `DATASYNCER_AUTOSHEET` (incl. `editDestination[:n]`) / `DATASYNCER_AUTORESTORE` / `DATASYNCER_WINDOW` exist for trying screens without real data — keep them harmless when unset. Screenshots: `screencapture -l <id>` works only on the main display, after `caffeinate -u`.
14a. **Confirmation dialogs:** the confirm button has no `.destructive` role (this macOS draws that as red text on a red fill — unreadable, reproduced Oct 14 2026) and Cancel carries `.keyboardShortcut(.defaultAction)`; the context-menu items keep the role (menus draw it fine).
14b. **Text fields in the editors are `PlainTextField` / `Field`** (an NSTextField the app owns), not SwiftUI's `TextField`: inside this window shell SwiftUI's field drops a trailing space from view until the next character (reproduced Oct 14 2026 with a probe that sends key events into the sheet). The base text size is 14 (set on both window roots); small labels are 12.5–14.
14c. **Copy the folder itself or its contents** is per destination (`Destination.includeSourceFolder`, nil = contents, the old behaviour): the runner sees the scan one level up (`Scanner.Result.nested`) and copies from the source's parent, so paths at the destination, in the records and in a restore all carry the folder's name. New destinations start on; the on/off switch lives on the job's page only.
14d. **The look lives in `Design.swift`** (Oct 14 2026, modelled on System Settings / Carbon Copy Cloner / Arq and the HIG): five type sizes (`DS.title/heading/section/body/secondary`, plus `DS.mono` for logs and `DS.stat` for tiles) — never a raw `.font(.system(size:))` for text (symbol sizes are fine); surfaces through `Card` / `GroupedCard` (`DS.surface/edge/shadow`, light: white + hairline + faint shadow, dark: lifted grey, no shadow), rows with `IconTile`, section headings title-case. Keep new views on these tokens.
15. **Appearance:** the views read colours from `Theme` (static, main thread), which `AppModel` re-applies from `settings` on every change; never hard-code the accent (`Theme.accent`, and `.buttonStyle(.link).foregroundStyle(Theme.accent)` for links). Themes are `CustomTheme`s in settings.json; the editor previews live by writing the theme into settings and restores the old settings on Cancel.
16. **Design:** Theme 1 "Sidebar" from the mockups (jobs down the left, the selected job's details on the right, Check / Restore… / Run… as real buttons at the top of the job's page (in the window toolbar macOS draws them grey), gear + New job at the bottom of the sidebar; a strip on the main window while a job runs with Watch / Cancel run; Settings opens from the gear: General, Appearance (one Theme list: Light / Dark / Follow the system / the user's own themes with Edit and delete, New… at the bottom; then the accent), Accounts, Notifications, Run history).
